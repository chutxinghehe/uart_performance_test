## Files Nên Commit vs Không Nên Commit

### ✅ NÊN COMMIT (Essential Files)

#### 1. **CubeMX Configuration**
```
✅ STM32_Project.ioc
```
**Tại sao:** File này define toàn bộ hardware configuration (pinout, clock, peripherals). Team cần file này để regenerate code.

**Conflict risk:** ⚠️⚠️⚠️ **RẤT CAO** nếu nhiều người configure CubeMX

#### 2. **Generated Source Code**
```
✅ Core/Src/*.c
✅ Core/Inc/*.h
✅ Core/Startup/*.s
```
**Tại sao:** Code này được generate từ `.ioc`, nhưng có **USER CODE sections** mà team viết code trong đó.

**Conflict risk:** ⚠️ **TRUNG BÌNH** (nếu 2 người viết code trong cùng USER CODE section)

#### 3. **HAL/LL Drivers**
```
✅ Drivers/STM32F1xx_HAL_Driver/
✅ Drivers/CMSIS/
```
**Tại sao:** Đảm bảo team dùng **cùng version** HAL driver (tránh incompatibility).

**Conflict risk:** ✅ **THẤP** (thư viện ít thay đổi)

#### 4. **Keil Project File**
```
✅ MDK-ARM/*.uvprojx
```
**Tại sao:** Define compiler settings, linker script, include paths. Team cần để build project.

**Conflict risk:** ⚠️ **TRUNG BÌNH** (nếu 2 người cùng add files vào project)

#### 5. **Linker Script**
```
✅ STM32F103XB_FLASH.ld  (nếu dùng GCC)
✅ (Linker script embedded trong .uvprojx nếu dùng Keil)
```
**Tại sao:** Define memory layout. Quan trọng cho build.

#### 6. **User Code (Custom)**
```
✅ User/Src/*.c
✅ User/Inc/*.h
```
**Tại sao:** Code logic của team, không phải generated code.

**Conflict risk:** ⚠️⚠️ **CAO** (nếu nhiều người sửa cùng module)

#### 7. **Documentation**
```
✅ README.md
✅ docs/*.md
```
**Tại sao:** Hướng dẫn setup, build, test.

#### 8. **Python Scripts**
```
✅ Python/tests/*.py
✅ Python/tools/*.py
✅ Python/requirements.txt
```
**Tại sao:** Test automation scripts team dùng chung.

## CubeMX Workflow

### Scenario 1: Init Project (Lần Đầu)

**Person A (Team Lead):**

1. **Tạo project trong CubeMX:**
   - Chọn MCU: STM32F103C8
   - Configure clock tree
   - Enable peripherals cơ bản (SYS, RCC)
   - Set project name, toolchain (MDK-ARM V5)
   - Generate code

2. **Init Git:**
```bash
cd STM32_Project

# Init git
git init

# Add .gitignore (xem section sau)
# Create .gitignore

# Add all files
git add .

# First commit
git commit -m "init: STM32 project with CubeMX base configuration"

# Push to GitHub
git remote add origin git@github.com:team/stm32-project.git
git branch -M main
git push -u origin main
```

3. **Announce team:**
```
"Project đã init trên GitHub, mọi người clone về:
git clone git@github.com:team/stm32-project.git"
```

---

### Scenario 2: Configure Peripherals (Nguy Hiểm!)

**⚠️ CẢNH BÁO:** File `.ioc` là **single point of conflict**. Nhiều người cùng configure = chắc chắn conflict!

#### Strategy 1: **CubeMX Coordinator** (Recommended cho beginner)

**Quy tắc:**
- Chỉ **1 người** (coordinator) được configure CubeMX
- Người khác **không** mở CubeMX, chỉ viết code trong USER CODE sections
- Khi cần enable peripheral mới, **request coordinator**

**Workflow:**

**Person B (cần CAN):**
```
Team chat:
"A ơi, mình cần enable CAN peripheral,
bạn có thể configure CubeMX giúp mình không?"
```

**Person A (coordinator):**
```bash
# Pull main mới nhất
git checkout main
git pull origin main

# Tạo branch
git switch -c config/enable-can

# Mở CubeMX
# Open STM32_Project.ioc
# Enable CAN1, configure pins
# Generate code

# Check changes
git status
# Output:
#   modified:   STM32_Project.ioc
#   modified:   Core/Src/main.c
#   modified:   Core/Inc/main.h
#   new file:    Core/Src/can.c
#   new file:    Core/Inc/can.h
#   modified:   MDK-ARM/STM32_Project.uvprojx

# Commit
git add .
git commit -m "config(cubemx): enable CAN1 peripheral on PB8/PB9"

# Push
git push -u origin config/enable-can

# Create PR, merge nhanh
```

**Person B:**
```bash
# Pull main sau khi merge
git checkout main
git pull origin main

# Giờ có can.c và can.h, bắt đầu code
git switch -c feature/can
# Code trong User/Src/app_can.c
```

#### Strategy 2: **Self-Service** (Cho team experienced)

**Quy tắc:**
- Mỗi người tự configure peripheral của mình
- **PHẢI announce** trước khi configure
- **Merge ngay** sau khi configure (không để lâu)
- **Không** configure 2 người cùng lúc

**Workflow:**

**Person B:**
```
Team chat (10:00 AM):
"Mình sẽ configure CubeMX enable CAN lúc 10:30,
ai cần merge code thì làm trước đó nhé."
```

**Person C (đang làm UART):**
```bash
# Rush commit và merge trước 10:30
git add .
git commit -m "feat(uart): complete UART driver"
git push origin feature/uart

# Create PR, merge nhanh
```

**Person B (10:30):**
```bash
# Pull main mới nhất
git checkout main
git pull origin main

# Configure CubeMX
git switch -c config/enable-can
# Open .ioc, enable CAN, generate

# Commit và merge NGAY
git add .
git commit -m "config(cubemx): enable CAN1"
git push -u origin config/enable-can

# Create PR, merge immediately

# Announce
"Done! CAN đã enable, mọi người pull main nhé."
```

### Scenario 3: Regenerate Code (Phổ Biến)

**Person A đã code trong `main.c`:**

```c
// Core/Src/main.c

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();
    
    /* USER CODE BEGIN 2 */
    // Person A viết code ở đây
    uint8_t msg[] = "Hello World\r\n";
    HAL_UART_Transmit(&huart2, msg, sizeof(msg), 100);
    /* USER CODE END 2 */
    
    while (1)
    {
        /* USER CODE BEGIN 3 */
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
        HAL_Delay(500);
        /* USER CODE END 3 */
    }
}
```

**Sau đó Person A cần enable thêm TIM2:**

```bash
# Mở CubeMX
# Enable TIM2
# Click "Generate Code"

# ⚠️ CubeMX hỏi:
# "Do you want to migrate your project?"
# → Click "Continue" (CubeMX sẽ giữ USER CODE)
```

**CubeMX làm gì:**
1. Đọc `main.c` cũ
2. Extract code trong `/* USER CODE BEGIN */.../* USER CODE END */`
3. Regenerate `main.c` mới
4. Insert lại USER CODE vào đúng vị trí
5. Add `MX_TIM2_Init()` call

**`main.c` sau regenerate:**

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();
    MX_TIM2_Init();  // ← CubeMX thêm
    
    /* USER CODE BEGIN 2 */
    // Code của bạn VẪN CÒN NGUYÊN!
    uint8_t msg[] = "Hello World\r\n";
    HAL_UART_Transmit(&huart2, msg, sizeof(msg), 100);
    /* USER CODE END 2 */
    
    while (1)
    {
        /* USER CODE BEGIN 3 */
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
        HAL_Delay(500);
        /* USER CODE END 3 */
    }
}
```

**Check changes:**
```bash
git diff Core/Src/main.c
# Output:
#   +MX_TIM2_Init();
#   +void MX_TIM2_Init(void) { ... }
```

**Commit:**
```bash
git add Core/Src/main.c Core/Inc/main.h Core/Src/tim.c Core/Inc/tim.h STM32_Project.ioc
git commit -m "config(cubemx): enable TIM2 for PWM"
```

## Generated Code Management

### USER CODE Sections

**CubeMX tạo các section để bạn viết code:**

```c
/* USER CODE BEGIN Includes */
// Thêm #include ở đây
/* USER CODE END Includes */

/* USER CODE BEGIN PV */
// Private variables
/* USER CODE END PV */

/* USER CODE BEGIN 0 */
// Function definitions
/* USER CODE END 0 */

/* USER CODE BEGIN 2 */
// Code trong main(), sau khi init
/* USER CODE END 2 */

/* USER CODE BEGIN 3 */
// Code trong while(1)
/* USER CODE END 3 */

/* USER CODE BEGIN 4 */
// Custom functions
/* USER CODE END 4 */
```

### ⚠️ QUY TẮC VÀNG

✅ **CHỈ viết code trong `/* USER CODE BEGIN/END */`**  
❌ **KHÔNG sửa code ngoài USER CODE sections**  

**Tại sao?**
- Code ngoài USER CODE sẽ bị **GHI ĐÈ** khi regenerate
- Code trong USER CODE được CubeMX **preserve**

**Ví dụ SAI:**

```c
// ❌ SAI: Viết code ngoài USER CODE section
int main(void)
{
    HAL_Init();
    
    // ❌ Code này sẽ BỊ MẤT khi regenerate!
    uint8_t msg[] = "Hello";
    
    /* USER CODE BEGIN 2 */
    /* USER CODE END 2 */
    
    while (1)
    {
    }
}
```

**Ví dụ ĐÚNG:**

```c
// ✅ ĐÚNG: Viết code trong USER CODE section
int main(void)
{
    HAL_Init();
    
    /* USER CODE BEGIN 2 */
    // ✅ Code này được BẢO VỆ!
    uint8_t msg[] = "Hello";
    HAL_UART_Transmit(&huart2, msg, 5, 100);
    /* USER CODE END 2 */
    
    while (1)
    {
    }
}
```

## Keil Project Files

### File `.uvprojx` - NÊN Commit

**File này chứa:**
- Compiler settings (optimization level, defines)
- Include paths
- Linker script
- Source files list
- Target configuration

**Team cần file này để:**
- Build project được
- Cùng compiler settings

**Conflict có thể xảy ra khi:**
- 2 người cùng add file vào project
- 2 người cùng thay đổi compiler settings

**Resolve conflict `.uvprojx`:**

```xml
<<<<<<< HEAD
<File>
  <FileName>app_can.c</FileName>  <!-- Person A add -->
=======
<File>
  <FileName>app_uart.c</FileName>  <!-- Person B add -->
>>>>>>> feature/uart
```

**Fix:** Giữ CẢ HAI files

```xml
<File>
  <FileName>app_can.c</FileName>
</File>
<File>
  <FileName>app_uart.c</FileName>
</File>
```

### File `.uvoptx` - KHÔNG Commit

**File này chứa:**
- Debugger settings (J-Link, ST-Link)
- Breakpoints
- Watch windows
- GUI layout

**Mỗi người config khác nhau** → Không commit

## CubeMX Conflict Resolution

### Conflict Trong File `.ioc`

**Tình huống:**

```
Person A: Enable CAN on PB8/PB9
Person B: Enable I2C on PB6/PB7
→ Cả 2 sửa STM32_Project.ioc
```

**File conflict:**

```xml
<<<<<<< HEAD
ProjectManager.PreviousToolchain=
ProjectManager.TargetToolchain=MDK-ARM V5
Mcu.Pin5=PB6
Mcu.Pin6=PB7
=======
ProjectManager.PreviousToolchain=
ProjectManager.TargetToolchain=MDK-ARM V5
Mcu.Pin5=PB8
Mcu.Pin6=PB9
>>>>>>> feature/can
```

### ⚠️ KHÔNG Resolve Thủ Công File `.ioc`!

File `.ioc` là **XML phức tạp**, resolve sai = project hỏng.

**Best practice:**

#### Option 1: Designate Winner

```bash
# Person B: Abort merge, dùng version của A
git merge --abort

# Announce team
"A ơi, mình thấy bạn cũng configure CubeMX.
Mình sẽ pull version của bạn và configure lại I2C sau."

# Pull version của A
git pull origin main

# Configure I2C lại trong CubeMX
# Generate code
git add .
git commit -m "config(cubemx): enable I2C after CAN merge"
```

#### Option 2: Manual Coordination

```bash
# Person A và B discuss trên call/chat
# Quyết định:
# - A pull code của B
# - A mở CubeMX
# - A enable thêm CAN (manual)
# - A generate code
# - A commit

git checkout main
git pull origin main  # Có I2C của B
# Mở CubeMX, enable CAN
git add .
git commit -m "config(cubemx): enable CAN (after I2C)"
```

## Best Practices

### 1. File Organization

**Tách USER CODE ra file riêng:**

```
Thay vì viết tất cả trong main.c:
→ Tạo User/Src/app_*.c

Core/Src/main.c:
  ↓
  Chỉ gọi init functions

User/Src/app_gpio.c:
  ↓
  Logic GPIO driver

User/Src/app_uart.c:
  ↓
  Logic UART communication
```

**Ví dụ:**

```c
// Core/Src/main.c (generated, ít conflict)
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USART2_UART_Init();
    
    /* USER CODE BEGIN 2 */
    App_GPIO_Init();  // Call user function
    App_UART_Init();
    /* USER CODE END 2 */
    
    while (1)
    {
        /* USER CODE BEGIN 3 */
        App_GPIO_Task();  // Call user function
        App_UART_Task();
        /* USER CODE END 3 */
    }
}
```

```c
// User/Src/app_gpio.c (custom, team control)
#include "app_gpio.h"

void App_GPIO_Init(void)
{
    // Person A viết logic ở đây
}

void App_GPIO_Task(void)
{
    // Toggle LED, etc.
}
```

**Benefits:**
- `main.c` conflict ít hơn (chỉ có function calls)
- Logic tách biệt → dễ review
- Dễ test (unit test từng module)

